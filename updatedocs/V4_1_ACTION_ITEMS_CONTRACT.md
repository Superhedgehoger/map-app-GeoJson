# Geomap v4.1 经营事项契约

## 业务目标

经营事项用于跟踪门店整改、选址调研、开业准备和日常运营动作。使用者直接记录“谁、在什么时间前、完成什么”，管理层通过逾期和优先级掌握执行风险。

## 状态

```text
todo（待处理） → doing（进行中） → done（已完成）
        ↑__________________________|
                重新打开
```

状态变化由 editor、admin 或 owner 直接操作并进入审计记录。viewer 只能查看。

## 字段

`WorkspaceActionItem` 包含事项 ID、工作区 ID、可选实体引用、标题、说明、优先级、状态、责任人、截止日期、创建人/时间、更新人/时间和完成时间。

- 标题：必填，最长 120 字符。
- 说明：可选，最长 4000 字符。
- 实体引用：可选，最长 200 字符，可对应门店或候选点 ID。
- 优先级：`low`、`medium`、`high`、`critical`。
- 截止日期：可选，使用 `YYYY-MM-DD`。
- 责任人：留空时默认为创建人；填写时必须是当前组织的有效成员邮箱。

## API

| 方法    | 路径                                             | 最低权限 | 用途             |
| ------- | ------------------------------------------------ | -------- | ---------------- |
| `GET`   | `/api/workspaces/:id/action-items`               | viewer   | 查看全部经营事项 |
| `POST`  | `/api/workspaces/:id/action-items`               | editor   | 新增经营事项     |
| `PATCH` | `/api/workspaces/:id/action-items/:actionItemId` | editor   | 更新事项状态     |

服务端校验工作区组织边界、成员角色、责任人归属、日期和枚举字段，并生成 `action-item.create` 与 `action-item.status.update` 审计事件。

## 界面与验收

- 协作总览显示逾期事项数量和全部未完成事项数量。
- 逾期事项使用红色状态边线，进行中和已完成分别使用蓝色与绿色。
- 用户可在同一页面新增事项并依次开始处理、标记完成或重新打开。
- 公开 Pages、Lite 和未连接私有 API 的单文件不发送事项数据。
