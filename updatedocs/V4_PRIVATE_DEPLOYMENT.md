# Geomap v4 私有部署与协作契约

## 定位与边界

v4 将“公开工具”和“企业数据服务”明确拆开：GitHub Pages、Lite 和离线单文件继续无需账号并默认只写浏览器；真实门店经营数据、成员、评论和审计只进入企业自行部署的私有 API。客户端不会自动探测服务，只有显式设置 `GEOMAP_PRIVATE_API_URL` 或 `?privateApi=https://…` 才会发出请求。

当前 Node 服务是单组织、单节点试点实现，使用原子替换的 JSON 文件保存业务数据，密码以独立盐值的 scrypt 摘要保存，会话只存在服务进程内。它适合内网试用、验收权限和工作流，不等同于高可用生产数据库。

## 快速试点

需要 Node.js 22+。在仓库根目录执行：

```bash
npm ci
cp server/.env.example .env
npm run private:server
```

环境变量：

| 变量                    | 默认值                             | 用途                                   |
| ----------------------- | ---------------------------------- | -------------------------------------- |
| `GEOMAP_PRIVATE_HOST`   | `127.0.0.1`                        | 监听地址；不要在无防火墙时改为公网地址 |
| `GEOMAP_PRIVATE_PORT`   | `8787`                             | API 端口                               |
| `GEOMAP_PRIVATE_DATA`   | `private-data/geomap-private.json` | 私有数据文件                           |
| `GEOMAP_ALLOWED_ORIGIN` | `http://127.0.0.1:5173`            | 唯一允许的浏览器来源                   |

打开 Full 版并添加 `?privateApi=http://127.0.0.1:8787`，第一次进入“协作”会创建组织、所有者和默认工作区。密码至少 12 位。真实环境必须将页面和 API 都置于 HTTPS 下，不得把凭据写进 URL。

## 权限矩阵

| 操作                               | viewer | editor | admin |  owner   |
| ---------------------------------- | :----: | :----: | :---: | :------: |
| 查看工作区、发表评论、生成简报     |   ✅   |   ✅   |  ✅   |    ✅    |
| 保存工作区、解决评论、创建只读分享 |   ❌   |   ✅   |  ✅   |    ✅    |
| 成员、同步任务、品牌和审计         |   ❌   |   ❌   |  ✅   |    ✅    |
| 创建其他 owner                     |   ❌   |   ❌   |  ❌   | 暂不开放 |

服务器在每个资源访问中再次校验组织和角色，不能依赖客户端隐藏按钮作为权限控制。成员邮箱全局唯一，添加成员时分配 viewer/editor/admin 之一。

## 一致性与冲突

工作区从 `version=1` 开始。保存时客户端必须发送 `If-Match: "当前版本"`；如果其他成员已保存，服务返回 `409 version-conflict` 及最新版本号、时间和操作者。客户端不会覆盖远端，用户必须拉取并重新核对修改。每次成功保存、评论、分享、成员或配置变化都会形成审计记录。

只读分享固化创建时的 Workspace schema v2 快照，不会随之后编辑变化，默认 7 天过期。URL token 等同临时访问凭据，应使用 HTTPS 并按敏感信息处理。

## 备份与恢复

1. 停止私有服务，避免复制过程中发生新写入。
2. 复制 `GEOMAP_PRIVATE_DATA` 指向的 JSON 文件到加密备份介质，并记录应用版本。
3. 在隔离环境用相同版本启动服务，检查 `/api/health`、登录、工作区版本和要素数量。
4. 恢复时先保留现有文件，再把验证过的备份放回配置路径，最后启动并执行浏览器只读核对。

至少保留每日、每周、每月三档备份，并定期做恢复演练。会话在重启后失效属于设计行为。

## 生产拓扑与升级阈值

推荐拓扑为“企业 HTTPS 静态站点 → 同域反向代理 `/api` → 私有服务 → 加密持久卷”，反向代理负责 TLS、请求大小、速率限制、访问日志和可信网络。不要直接暴露 Node 端口。

出现以下任一情况时，应把 JSON 试点服务迁移到 PostgreSQL（空间检索再增加 PostGIS），附件进入对象存储：多实例/高可用、并发写入、数十个以上活跃成员、文件超过约 100 MB、需要数据库级恢复点、外部身份提供商、细粒度行权限或法规审计。迁移必须保留 Workspace schema、版本号、组织边界和审计时间线。

## 同步适配器

v4 beta 只保存 `webhook` 或 `file-drop` 任务的名称、间隔、启用状态和最近运行元数据，不在应用进程里执行定时器。实际调度应由企业任务系统触发，并复用 v3.4 的字段映射、复合主键、质量预览和修订规则；任何适配器都不得绕过质量门禁直接改写 Store。

## 验收

- `npm run check`：类型、格式、单元、服务端和兼容测试。
- `npm run test:e2e`：Full/Lite、登录、保存、409 冲突、公开模式与离线单文件。
- `/api/health` 不泄露成员、路径或配置密钥。
- 未配置私有 API 时不产生企业网络请求；Lite 始终关闭私有协作能力。
